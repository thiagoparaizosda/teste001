Como funciona o Recálculo de Track Participation (TP)

O recálculo aplica um novo Track Participation (TP) a uma CCO, ajustando os valores financeiros pelo fator de correção abaixo. Existem dois modos, com comportamentos bem diferentes:

O que muda: só os campos financeiros da raiz da CCO. Cada um dos 12 campos abaixo é multiplicado diretamente pelo fator de correção — não há cálculo composto, é uma escala simples de cada campo:

campo_novo = campo_original × fator_correcao

  • valorLancamentoTotal, valorNaoReconhecido, valorReconhecido, valorReconhecivel
  • valorNaoPassivelRecuperacao, valorReconhecidoExploracao, valorReconhecidoProducao
  • valorRecusado, overHeadExploracao, overHeadProducao, overHeadTotal
  • valorReconhecidoComOH — também escalado diretamente pelo fator (não é recalculado como "valorReconhecido + overHeadTotal")

O que NÃO muda:

  • O array correcoesMonetarias — nenhuma correção existente é lida ou alterada, nenhuma nova correção é criada.
  • flgRecuperado — permanece como estava.
  • quantidadeLancamento — apesar de aparecer no comparativo do resultado, este modo não recalcula esse campo (limitação atual).

O que muda: a raiz e, se já existir histórico, uma nova correção — mas as duas são calculadas de forma independente, cada uma a partir do seu próprio valor anterior. Uma não é derivada da outra:

  1. Raiz: recalculada sozinha, exatamente como no modo Somente Raiz — cada campo é multiplicado pelo fator de correção a partir do valor original da própria raiz.
  2. Sem nenhuma correção monetária no histórico: o recálculo termina aqui — nenhuma correção é criada (mesmo resultado do modo Somente Raiz).
  3. Com histórico: cria exatamente uma nova correção do tipo RETIFICACAO, calculada a partir da última correção existente (nunca da raiz) — as correções anteriores nunca são recalculadas, não importa se são 2 ou 50. Os valores dessa nova correção não são copiados para a raiz.

Cálculo de "Valor Reconhecido com OH" da nova correção — depende se a CCO já estava recuperada:

CCO recuperada (flgRecuperado = true):
diferença = (último "Valor Reconhecido com OH" não-zero do histórico × fator) − esse mesmo valor
nova correção.valorReconhecidoComOH = diferença
nova correção.diferencaValor = diferença

Essa diferença representa o "ganho" trazido pela correção de TP, que passa a ficar disponível como novo saldo recuperável da CCO.

CCO não recuperada:
nova correção.valorReconhecidoComOH = valor atual (última correção/raiz) × fator
nova correção.diferencaValor = 0

diferencaValor é sempre gravado como 0 neste caminho — comportamento atual do sistema, não uma fórmula matemática (é uma limitação conhecida, não uma regra de negócio).

Mudança de status de recuperação: o flgRecuperado da raiz só volta de true para false quando as duas condições acontecem: a CCO já era recuperada e o novo "Valor Reconhecido com OH" calculado for positivo.

valorRecuperado/valorRecuperadoTotal são copiados da última correção sem aplicar o fator — eles não entram na conta de valorReconhecidoComOH/diferencaValor acima.

Fator de Correção e Variação (iguais nos dois modos)
fator_correcao = TP Correção ÷ TP Original
variação (%) = ((TP Correção − TP Original) ÷ TP Original) × 100
